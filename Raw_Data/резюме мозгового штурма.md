## 00\. КОНТЕКСТ И ЦЕЛИ ПРОЕКТА

### Что строим

**AI-платформа для категорийного менеджера (Catman)** в ритейле — гибрид BI-дашборда и AI-агента с human-in-the-loop воркфлоу. Аналог «QlikView + ChatGPT + автоматизация back-office».

### Для кого

| Роль | Первичная потребность |
| --- | --- |
| **Catman** | Освободиться от Excel, стать стратегом |
| **Коммерческий директор** | Контроль маржи, сильные переговоры |
| **C-level / CEO** | ROI, governance, масштабируемость |
| **Инвесторы** | Proof of concept + defensible moat |

### Три кита философии

1. **Боль первична** — не «AI крутой», а «решение успевает за рынком»
2. **Агент + человек**, а не вместо
3. **Демо ≠ потёмкинская деревня** — честная система с ограничениями лучше игрушки без них

## 01\. ТЕХНИЧЕСКИЙ СТЕК — n8n 2.0

### Архитектура

[7](https://finbyz.tech/n8n/insights/n8n-2-0-langchain-agentic-workflows) n8n 2.0 вышел в январе 2026 года. С интеграцией нативной поддержки LangChain n8n эволюционировал в мощный оркестрационный слой для AI-агентов — систем, способных рассуждать, планировать и выполнять задачи с помощью инструментов. [2](https://www.jahanzaib.ai/blog/n8n-ai-agent-workflows-practitioner-guide) 70+ специализированных AI-нод покрывают весь агентный стек: можно подключить любую LLM, хранить память разговора в Redis, Postgres или буферах, и выставить любой суб-воркфлоу как вызываемый инструмент, который агент выбирает сам.

**Четыре обязательных компонента каждого AI-агента в n8n:**

[5](https://techelix.co/blogs/n8n-ai-agent-development-langchain/)
- **Мозг (Model Node)** — подключение GPT-4o, Claude 3.5 или локальной Llama 3. Отвечает за рассуждение.
- **Память (Chat Memory Node)** — без неё агент «забывает» всё при завершении воркфлоу. Window Buffer для коротких диалогов, Summary Memory для долгих проектов.
- **Инструменты (Agent Tool Node)** — агент может искать в Google, запрашивать SQL-базу или вызывать другой n8n-воркфлоу как подпрограмму.
- **Ограждения (Output Parser Node)** — гарантирует, что AI выдаёт структурированные данные (JSON), а не просто «разговаривает».

### ✅ Лучшие практики

**Human-in-the-Loop (HITL) через Wait Node:**

[5](https://techelix.co/blogs/n8n-ai-agent-development-langchain/) В 2026 году «автономный» не значит «без надзора». Для высокорисковых операций n8n использует Wait Node как «Approval Gate»: когда агент достигает чувствительного шага, воркфлоу автоматически паузируется. Рецензент видит рассуждение агента, принимает финальное решение и нажимает «Approve». AI обеспечивает скорость, человеческое суждение — этическую целостность.

**Tiered LLM routing для экономии:**

[10](https://chronexa.io/blog/n8n-ai-agents-features-2026-complete-guide) Простые высокообъёмные запросы (FAQ, поиск данных, классификация) маршрутизируются к лёгким моделям типа GPT-4o-mini. Сложные задачи с неоднозначными входными данными — к более мощным, таким как Claude 3.5 Sonnet. Практики сообщают о снижении затрат на агента на 60% и более в продакшне при правильной настройке маршрутизации.

**Self-hosted для агентных нагрузок:**

[8](https://automationatlas.io/guides/building-ai-agents-with-n8n-2026/) Для агентных нагрузок self-hosting часто предпочтителен: долгие вызовы модели (10–60 секунд) потребляют cloud execution time, латентность vector store зависит от co-location с рантаймом n8n, локальные модели через Ollama требуют self-hosted ноды с GPU.

### ⚠️ Подводные камни

| Камень | Описание | Решение |
| --- | --- | --- |
| **Итерационный цикл** | Агент может зациклиться и сжечь API-бюджет | Установить `maxIterations` в AI Agent node |
| **Чувствительные данные в логах** | История выполнений захватывает все I/O по умолчанию | Настроить `EXECUTIONS_DATA_PRUNE` |
| **HITL без таймаута** | Воркфлоу висит, если рецензент не отвечает | Wait node timeout + эскалация |
| **Три отказа в продакшне** | [8](https://automationatlas.io/guides/building-ai-agents-with-n8n-2026/) Три failure modes доминируют в агентных нагрузках: таймауты модели, ошибки инструментов, бесконечные циклы | Error workflow + алерт в Telegram |
| **HITL только в браузере** | Нет инлайн-апрувала в Slack/Teams | Дополнить Slack-уведомлением с кнопкой |

## 02\. ИНСТРУМЕНТ ПОСТРОЕНИЯ — Claude Code + n8n MCP

### Как работает

[40](https://www.roborhythms.com/claude-n8n-workflow-2026/) Сдвиг от «Claude как советника» к «Claude как строителя» произошёл, когда n8n получил поддержку MCP в начале 2026 года. До этого можно было вставить JSON воркфлоу в Claude и попросить помощи — полезно, но всё ещё вручную. Теперь Claude имеет живой read/write доступ к вашему инстансу n8n — может проектировать воркфлоу с нуля, деплоить их, находить поломки и итерировать в реальном времени. [33](https://blog.n8n.io/n8n-mcp-server/) n8n MCP server теперь умеет строить воркфлоу из промпта (а не только запускать их). Можно создавать новые с нуля и обновлять существующие прямо в вашем инстансе n8n. Вы сообщаете AI-клиенту, что хотите — он строит воркфлоу, валидирует, запускает и исправляет сам себя при ошибке. Никакой возни с JSON-файлами или копирования ошибок.

**Официальная рекомендация n8n:**

[37](https://docs.n8n.io/connect/connect-to-n8n-mcp-server) Используйте coding agents (таких как Claude Code или Google ADK agents) вместо chat-клиентов. Coding agents оптимизированы для генерации и валидации TypeScript-кода, что делает их идеальными для программной сборки воркфлоу.

**n8n-MCP в цифрах:**

[31](https://github.com/czlonkowski/n8n-mcp) n8n-MCP предоставляет структурированный доступ к 2174 n8n-нодам (826 core + 1348 community). Охват свойств нод — 99%, AI-capable варианты — 265 инструментов с полной документацией, 156 реальных конфигураций из популярных шаблонов.

### ✅ Лучшие практики

**Skills для Claude Code** — ключевой инструмент качества:

[39](https://github.com/czlonkowski/n8n-mcp/blob/main/docs/CLAUDE_CODE_SETUP.md) n8n-skills репозиторий предоставляет 7 дополнительных навыков, обучающих AI-ассистентов строить production-ready n8n воркфлоу: Expression Syntax, MCP Tools Expert, Workflow Patterns, Validation Expert, Node Configuration, Code JavaScript, Code Python.

**Как писать задачу Claude:**

[40](https://www.roborhythms.com/claude-n8n-workflow-2026/) Опишите цель воркфлоу одним абзацем заранее. Включите: триггер (что запускает), источник данных (откуда информация), трансформации (что делать), вывод (куда результаты), расписание или частоту.

**Изоляция для безопасности:**

[38](https://blog.4sapi.com/blog/n8n-mcp-build-automation-workflows-with-claude-code) Никогда не позволяйте AI редактировать production-воркфлоу напрямую — сгенерированная логика может содержать непредвиденные ошибки. Используйте отдельный тестовый инстанс n8n для AI-генерируемых воркфлоу. Валидируйте и тестируйте перед экспортом JSON и импортом в продакшн.

### ⚠️ Подводные камни

| Камень | Описание |
| --- | --- |
| **40–50% готовности, не 100%** | Claude Code не выдаёт финальный воркфлоу с первого промпта — нужны итерации |
| **Credentials — только вручную** | [32](https://www.mindstudio.ai/blog/n8n-mcp-server-claude-code-workflows) MCP-сервер может создать ноды, требующие credentials (Gmail, Slack, HubSpot), но не может хранить их. Их нужно добавить в n8n UI после создания воркфлоу. |
| **Одно изменение за раз** | [32](https://www.mindstudio.ai/blog/n8n-mcp-server-claude-code-workflows) Не делайте слишком много изменений в одном промпте. Разбивайте сложные изменения на меньшие шаги. |
| **Новые воркфлоу неактивны** | [32](https://www.mindstudio.ai/blog/n8n-mcp-server-claude-code-workflows) Забытая активация воркфлоу после сборки — стабильная ошибка. Если воркфлоу использует scheduled trigger или webhook, попросите Claude Code активировать его, когда будете готовы. |

## 03\. ФРОНТЕНД — Streamlit (MVP) → CopilotKit (Production)

### Принципиальная позиция

[11](https://www.copilotkit.ai/blog/the-developer-s-guide-to-generative-ui-in-2026) UI-слой в AI-агентных приложениях в основном остался прежним — и это сдерживает опыт. Большинство агентных взаимодействий всё ещё полагаются на чат, даже когда задача явно требует форм, превью, элементов управления или пошаговой обратной связи.

**Простой чат-бокс — не правильный ответ.** Правильный ответ — **дашборд + встроенный чат + approval gate**.

### Фаза 1 — MVP (Streamlit, 4–6 недель)

Для быстрых пилотов Streamlit даёт лаконичный способ поднять визуальный прототип, особенно если оркестрационный фреймворк тоже на Python.

```
textn8n (backend агент) → webhook → Streamlit (UI)
```

**Структура экрана MVP:**

```
text┌─────────────────────────────────────┐
│ KPI-карточки (остатки, маржа, алерт)│
├──────────────────┬──────────────────┤
│ График/таблица   │ Чат-сайдбар      │
│ (основной экран) │ с агентом        │
├──────────────────┴──────────────────┤
│ Approve / Reject / Edit кнопки      │
└─────────────────────────────────────┘
```

### Фаза 2 — Production (CopilotKit + AG-UI)

**Почему CopilotKit для продакшна:**

[17](https://techcrunch.com/2026/05/05/copilotkit-raises-27m-to-help-devs-deploy-app-native-ai-agents/) CEO CopilotKit объяснил: разработчики могут использовать фреймворк для предоставления спецификаций и строительных блоков для динамических пользовательских интерфейсов, которые AI-агент может использовать для генерации UI под контекст. «Агент может отвечать вам не просто блоками текста, а интерактивными UI, определёнными вашей собственной компанией». [12](https://github.com/copilotkit/copilotkit) Generative UI позволяет агентам генерировать и обновлять UI-компоненты динамически в runtime на основе намерения пользователя и состояния агента. Shared State — синхронизированный слой состояния, который и агенты, и UI-компоненты могут читать и писать в реальном времени. Всё это для React, Angular, Mobile, Slack и других платформ.

**Три паттерна Generative UI:**

[14](https://github.com/CopilotKit/generative-ui) В экосистеме CopilotKit Generative UI реализован в трёх паттернах: Controlled Generative UI (высокий контроль, низкая свобода) → AG-UI; Declarative Generative UI (общий контроль) → A2UI, Open-JSON-UI; Open-ended Generative UI (низкий контроль, высокая свобода) → MCP Apps / Custom UIs.

**Для Catman-платформы рекомендуется Controlled Generative UI** — разработчик заранее собирает компоненты (таблица, график, карточка апрувала), агент выбирает какой показать и передаёт данные.

**Переход Фаза 1 → Фаза 2:**

[12](https://github.com/copilotkit/copilotkit) Логика агента остаётся той же — AG-UI обрабатывает wire protocol, CopilotKit обрабатывает UI-слой для каждого фреймворка. n8n-воркфлоу не переписываете — меняете только фронтенд.

**Важный подводный камень CopilotKit:**

[11](https://www.copilotkit.ai/blog/the-developer-s-guide-to-generative-ui-in-2026) CopilotKit сменил модель на fable-5 в один вторник — и к среде набежал счёт в $22 000 от Anthropic. Никакого бага не было — пять инженеров делали обычную работу, но новая модель интерпретировала правила значительно свободнее. \*\*Вывод:\*\* всегда устанавливайте cost cap перед сменой модели.

### 🔴 Открытые боли (O)

**О-1: «Данные есть — доверия нет»**

[21](https://spendmatters.com/2025/12/16/category-management-key-insights-from-creactives-for-2026/) Повторяющаяся боль: недоверие к данным, которое препятствует согласованию между закупками, финансами и операциями. Без единого data-фундамента стратегии категорий остаются разрозненными, локальными и трудно масштабируемыми.

💡 **"Вау"-идея:** кнопка «Объясни это число» — агент раскрывает источник, период, погрешность каждой KPI-карточки

---

**О-2: «Я трачу время не на стратегию»**

[30](https://blog.duvo.ai/how-to-improve-retail-category-management-with-ai) Согласно исследованию Kantar 2025 Category Leadership Study, категорийные менеджеры тратят часы ежедневно на поиск и анализ данных, оставляя мало времени для стратегического мышления и инноваций. Это ведёт к упущенным продажам, эрозии маржи и нереализованным возможностям.

💡 **"Вау"-идея:** счётчик «Агент взял на себя X часов рутины на этой неделе. Вы потратили их на: \[список стратегических задач\]»

---

**О-3: «Переговоры — лотерея»**

[22](https://evrimagaci.org/gpt/category-management-transforms-with-ai-and-new-leadership-523730) Многие команды «остаются чрезмерно зависимыми от разведки, предоставляемой поставщиком, создавая информационную асимметрию во время переговоров».

💡 **"Вау"-идея:** X-ray поставщика — профиль уязвимости перед переговорами: доля рынка, история SLA, паттерны уступок

---

**О-4: «Инвентарь — постоянная боль»**

[24](https://retano.ai/retano-catman-next-gen-ai-powered-category-management-solution/) Это ведёт к неэффективности: перестокованным непродавцам и дефициту высококонвертируемых товаров. По данным IHL Group, глобальные ритейлеры потеряют около $1.77 триллиона из-за inventory distortion — дефицитов и избытков.

💡 **"Вау"-идея:** проактивный алерт в 08:00 — агент нашёл проблему сам ещё до того, как Catman открыл систему

---

### 🟠 Латентные боли Catman (Л)

**Л-1: «Я не стратег — я Excel-оператор»** Это профессиональная боль идентичности. [28](https://www.kodiakhub.com/blog/ai-category-management-software) AI не заменяет категорийных менеджеров. Он устраняет рутину — ручные выгрузки, VLOOKUP-гимнастику, ночные пожары — чтобы вы делали то, в чём превосходны люди: строили сильные партнёрства с поставщиками.

💡 **"Вау"-идея:** не «сэкономили X часов» (про эффективность), а «вы потратили это время на стратегию» (про **достоинство и идентичность**)

---

**Л-2: «Меня не слышат на совещаниях»** Catman приходит с рекомендацией — и слышит «а ты уверен в этих данных?»

💡 **"Вау"-идея:** «Один клик — готовая презентация» — агент генерирует слайды для защиты решения перед КД: находки, рекомендации, источники, альтернативные сценарии

---

**Л-3: «Я боюсь ошибиться»** Catman принимает решения с большим радиусом поражения на тысячах SKU. Это когнитивный стресс.

💡 **"Вау"-идея:** «Агент как страховая сетка» — перед каждым решением показывает три сценария развития событий, худший случай, что мониторить. Не автоматизация решения — снижение страха его принятия

---

### 🟡 Латентные боли Коммерческого директора (Л-КД)

**Л-КД-1: «Я не знаю, где реально утекает маржа»**

[30](https://blog.duvo.ai/how-to-improve-retail-category-management-with-ai) Эти проблемы складываются в ощутимые бизнес-последствия: упущенные продажи из-за дефицита, эрозия маржи из-за перестокованных медленных товаров и нереализованные возможности для оптимизации ассортимента.

💡 **"Вау"-идея:** «Маржинальный детектор» — мониторинг структурных утечек в реальном времени: walk rate по конкретным SKU, промо-каннибализация, скрытое влияние дефицита поставщика на 3 другие категории

---

## 1\. Stakeholder Needs Map (Открытые + Латентные)

### 1.1 Category Manager (Catman)

**Открытые (осознанные) потребности:**

- Меньше времени на Excel / data gathering / reporting / подготовку презентаций к review.
- Быстрые insights по OOS, overstock, slow-movers, promo ROI, assortment.
- Понятные рекомендации + возможность действовать (не просто «смотри дашборд»).
- Единый view данных (сейчас silos: POS, inventory, supplier, loyalty, e-com).

**Латентные («мурашки»):**

- Агент, который **сам** находит проблему утром (до того, как Catman открыл ноутбук) и приносит готовый план с рисками + estimated $ impact.
- HITL-контроль: «я нажимаю Approve — и оно уходит в WMS/ERP/письмо поставщику». Страх «AI сделает необратимое» снимается.
- Агент помнит контекст сцены и не галлюцинирует за её рамками (scoped).
- «Это не игрушка — это junior-аналитик + executor, который работает 24/7 и не ошибается в рутине».

### 1.2 Commercial Director / Head of Merchandising

**Открытые:**

- Рост маржи + выручки категории / сети.
- Контроль promo leakage, pricing consistency, assortment productivity.
- Скорость и качество решений (Category Review, supplier negotiations).
- Visibility по кластерам магазинов / локализации.

**Латентные:**

- Еженедельный «Margin Leakage Hunter» + recoverable $ с приоритетами.
- Готовый Negotiation Brief / Category Review Deck за минуты (лучше, чем делают аналитики за 1–2 дня).
- What-if симулятор, который мгновенно считает impact на sales/margin/OOS.
- Мульти-агентная оркестрация: один gatekeeper + специализированные sub-agents (запасы, promo, assortment).

### 1.3 C-level (CEO / CFO / COO / Board)

**Открытые:**

- Inventory as C-suite imperative (working capital, OOS lost sales, markdowns).
- Margin expansion в условиях pricing headwinds.
- Productivity (AI → меньше headcount growth при росте сложности).
- Risk control + auditability.

**Латентные (самые сильные «мурашки»):**

- End-to-end value loop: Detect → Recommend → Human Approve → Execute → Measure (в одной системе).
- Реал-тайм / near-real-time «деньги на экране»: «эта неделя спасли X ₽ выручки / Y ₽ маржи / Z часов Catman’ов».
- Прозрачность + детерминированный control (HITL на high-risk tools) → снимает страх «black box AI».
- Платформа, а не point-solution: «мы строим agentic workspace для continuous category optimization».
- Доказанный industry upside: GenAI unlock $240–390B retail value (margin +1.2–1.9 pp); agentic merchandising — sales lift до ~5%, margin до ~3% (McKinsey).

**Карта влияния:**  
C-level покупает vision + risk-mitigation + $ impact.  
ComDir покупает speed + quality of decisions + margin.  
Catman покупает time back + superpowers + trust (HITL).

## 3\. Principles of «Bullseye» & Goosebumps Design

1. **End-to-end loop** обязателен для максимального wow: Detect (сам) → Analyze → Recommend (с $ + risks) → HITL Approve/Edit/Reject → Execute (mock/real systems) → Measure & learn.

3. **Human-in-the-loop на high-risk** (write to ERP/WMS, large orders, delist, emails high-impact).
4. **Generative UI / Dashboard-first + chat sidebar** (не pure chat).
5. **Quantified impact** всегда на экране (saved revenue, margin, hours, OOS prevented).
6. **Latent trigger:** «Это глубже, чем я думал, и уже готово к действию с моим контролем».

## АКТ 3 — Стратегическое развитие (Catman как "архитектор")

### Сцена 3.1: «Ассортиментный аудит» — что делистить без боли

**Боль:**

[12](https://blog.duvo.ai/how-to-automate-retail-category-management-ai-agents) Когда категорийному менеджеру нужно \*\*делистить 100 SKU и предложить замены\*\*, AI-агент проверяет уровни запасов, открытые заказы на закупку и контрактные обязательства.

**Идея:** Агент еженедельно формирует «список кандидатов на делистинг» с полным обоснованием: оборачиваемость, вклад в трафик, наличие замены, контрактные риски. Catman видит не просто «эти SKU плохие» — а **полный контекст решения**.

## Что вы интуитивно нащупали

Вы описываете классическую проблему **scoped AI chat** — когда агент технически может ответить на что угодно, но **бизнес-логика требует ограничений**. Это решаемо, и решается на двух уровнях одновременно.

## Уровень 1: Техническое ограничение чата (System Prompt + Tools)

Агент знает только то, **какие инструменты ему доступны**. Если в MVP реализованы только 3 сцены — агент получает только 3 инструмента. Остальное физически недоступно.

```
textSYSTEM PROMPT агента (MVP-версия):

"Ты — аналитический помощник категорийного менеджера.
Ты можешь помочь с:
  1. Анализом остатков и дефицитов по категории
  2. Перераспределением товара между магазинами
  3. Срочным дозаказом у поставщиков

Если пользователь спрашивает о других задачах —
отвечай: 'Эта функция сейчас в разработке.
Опишите задачу — мы добавим её в следующий релиз.'
НЕ пытайся выполнить то, что не входит в твои инструменты."
```

**Что это даёт:**

- Агент не галлюцинирует и не обещает лишнего
- Пользователь получает честный ответ, а не ошибку
- Формулировка «опишите задачу» автоматически **собирает backlog** от реальных пользователей

### ❌ Вариант А: «Полная версия»

**Проблема:** создаёт ощущение, что MVP — это недоделка. C-level начинает ждать «настоящего» продукта и обесценивает MVP.

### ✅ Вариант Б: «Кейсы оптимизации» (ваш термин — он правильный)

textMVP = решает боль №1 (остатки/дефицит)

- Легко продавать следующий кейс: «мы сохранили 156k ₽ на остатках — теперь давайте возьмём промо»

### Как это работает в MVP

1. **Сцены (workspaces / modules)**  
	Дашборд делится на чёткие сцены (вкладки, карточки или переключатели).  
	Пример для вашего демо:
	- **Сцена 1 (MVP-ядро)**: «Здоровье запасов / Out-of-stock & Redistribution» (молочка, 47 магазинов, alerts, план перераспределения + дозаказ + письмо поставщику + HITL Approve).
		- (Опционально в MVP) **Сцена 2**: «Быстрый анализ ассортимента / SKU performance» — только чтение + рекомендации, без исполнения.
2. **Чат привязан к активной сцене**
	- Когда Catman находится в «Здоровье запасов», агент видит контекст этой сцены (данные, предыдущие шаги, выбранные магазины/SKU).
		- Можно задавать **любые уточняющие вопросы и задания в рамках сцены**:  
		«Почему именно эти 11 магазинов?»,  
		«Что если увеличить дозаказ на 20%?»,  
		«Покажи прогноз упущенной выручки к пятнице по кластеру»,  
		«Сгенерируй альтернативный план с другим поставщиком»,  
		«Добавь в план уведомление региональному менеджеру».
		- Агент имеет **только разрешённые tools** для этой сцены (SQL-запросы по остаткам/продажам, генерация плана, создание задач в WMS/ERP-mock, черновик письма, HITL-гейт).
		- Off-scope вопросы (ценообразование, промо-календарь, полный delisting, переговоры с поставщиком по контракту и т.д.) → gatekeeper-агент отвечает:  
		«Это выходит за рамки текущей задачи “Здоровье запасов”. Переключитесь на сцену “Ценообразование и маржа” или “Ассортиментная стратегия” (доступно в полной версии). Хотите, я сохраню текущий контекст?»
3. **Почему scoped, а не полностью свободный чат**
	- Надёжность демо и production: меньше галлюцинаций, предсказуемое поведение, контролируемые costs.
		- Соответствует best practices: начинать с explicit goals, scopes и guardrails; давать агенту narrow, job-specific tool surface.
		- Доверие C-level: «агент не делает что угодно, а работает строго в зоне ответственности + human approval на критических действиях».
		- Легко расширять: каждая новая сцена = новый набор tools + system prompt + (опционально) отдельный sub-agent.

### Это не «CopilotKit плохой» — это вопрос стека и скорости

[2](https://dev.co/ai/frameworks/copilotkit) CopilotKit — \*\*frontend-heavy\*\* инструмент. Если у вас нет React/Next.js как основного стека, а команда работает на Python — возникает интеграционная трения, потому что основной язык CopilotKit — TypeScript/JavaScript. Для вашего MVP это решающий фактор: **скорость до демо** важнее архитектурной красоты.

## Но вот в чём CopilotKit объективно сильнее Streamlit

[17](https://www.marktechpost.com/2026/05/21/how-copilotkit-is-redefining-the-agentic-ai-stack-in-2026/) Большинство AI в современном ПО — это чат-бот, прикрученный к углу приложения. CopilotKit утверждает, что агенты должны \*\*жить внутри приложений\*\*, понимать контекст, совершать действия и рендерить интерактивный UI — а не возвращать стены текста. [8](https://www.developersdigest.tech/guides/ai-agent-frameworks-compared) CopilotKit выигрывает, когда пользователям нужны \*\*shared state, апрувалы, frontend-инструменты и видимый агентный опыт внутри продукта\*\*. Большинство команд при этом всё равно сочетают его с backend-фреймворком типа Mastra или LangGraph. [11](https://www.copilotkit.ai/blog/the-developer-s-guide-to-generative-ui-in-2026) Generative UI (GenUI) — это паттерн, при котором части UI \*\*генерируются, выбираются или управляются AI-агентом в runtime\*\*, а не полностью предопределены разработчиками. Вместо хардкода каждой кнопки или формы заранее — UI создаётся динамически на основе потребностей пользователя и контекста. Агент может решать, какой UI показать, какие inputs ему нужны от пользователя и как должно обновляться состояние по ходу задачи.

Именно это даёт **"вау"-эффект** в вашем Approve-блоке: таблица появляется не как текст, а как живой React-компонент.

| Творог 9% | 5 из 11 | 0.8 | 31,000 ₽ | Срочный дозаказ |

**Почему это "вау":**

[6](https://www.jotform.com/ai/agents/n8n-ai-agent-workflow-example/) OpenAI определяет намерение за вашим запросом на естественном языке, запрашивает PostgreSQL для получения сырых данных и использует классификатор текста для определения, нужна ли визуализация. SQL query visualizer даёт возможность любому без навыков SQL визуализировать инсайты по запросу — это огромная экономия времени для аналитиков, выявляющих тренды.

Вы показываете именно этот паттерн, но в контексте реального Catman-кейса.

### 🎬 Сцена 4 (4:30–5:30) — «Catman нажимает Approve — и видит, что происходит»

**Это ключевой момент демо. Здесь C-level видит "серьёзность".**

- ❌ **Отклонить** — с объяснением причины (агент учтёт в следующий раз)

Catman нажимает **«Одобрить всё»**. На экране — лайв-прогресс:

[12](https://blog.duvo.ai/how-to-automate-retail-category-management-ai-agents) После одобрения агенты выполняют изменения в подключённых системах. Это может включать обновление цен в ERP, настройку промо в CMS электронной коммерции, корректировку заказов в порталах поставщиков. ## Акт 4 — Что НЕ делать в этом демо

| ❌ Ловушка | ✅ Как избежать |
| --- | --- |
| Показывать агента, который "думает вслух" 40 секунд в прямом эфире | Заготовьте кэшированный ответ на демо-запрос. Живой вызов — только для Q&A |

| Чат без истории | Включите memory buffer — агент должен помнить контекст предыдущего вопроса |

### Конкретный end-to-end сценарий демо (скрипт презентации)

**1\. Открытие — Dashboard (30–45 сек, «это не игрушка»)**  
Показываем профессиональный BI-интерфейс:

- KPI-карточки: Category sales, margin %, stockout rate, assortment coverage by cluster.
- Интерактивные графики: кластеризация магазинов (scatter/map), top/bottom SKUs, тренды, heatmap gaps.
- Список активных расписаний («Weekly Assortment Audit — next run in 3 days»).
- Sidebar: чат-копайлот + кнопка «New Analysis / Run Audit».  
	*Вау*: Выглядит как QlikView/Power BI + AI, а не чат-бот.

**2\. Триггер анализа (пользователь/Catman)**  
Вариант А (freeform): «Проанализируй ассортимент soft drinks в магазинах Cluster A. Найди gaps, overstocks, рекомендуй изменения на следующий месяц с учётом сезонности и цен конкурентов. Покажи impact на sales/margin».  
Вариант Б (кнопка): «Run Weekly Assortment Audit for Cluster A».

**3\. Multi-agent orchestration + прозрачность (2–3 мин, сильный wow)**  
Supervisor Agent планирует и делегирует (видно в UI progress / tool-use disclosure / planning visibility):

- Data Analyst Agent — запросы в БД, агрегации, кластеры.
- Assortment Optimizer Agent — scoring, scenario simulation, рекомендации.
- Risk/Compliance Agent — флаги high-impact, constraints.

Показываем:

- Статус-стрим («Querying sales last 90 days… Clustering stores… Running optimization…»).
- Intermediate results (таблицы, мини-графики).
- Memory (ссылки на прошлые решения).

*Вау*: Видно «команду агентов», а не чёрный ящик. Multi-step tracking + recovery.

**4\. Результат + Generative UI (2–3 мин)**

- Текстовый executive summary + structured table (SKU | Action: Add/Remove/Resize/Keep | Expected Δ sales/margin | Confidence | Why).
- Динамические графики: before/after assortment, impact simulation, gap heatmap.
- What-if: «Что если оставим SKU X?» → мгновенный пересчёт (агент перезапускает tool).
- Экспорт PDF-отчёта.

**5\. Human-in-the-Loop Approval (ключевой trust + robustness, 2–3 мин)**  
Большой блок Review:

- Catman видит рекомендацию, может edit (inline или через чат), задать уточнения.
- Кнопки: Approve → Push to Back-office / ERP | Edit & Resimulate | Deny | Escalate.
- При Approve срабатывает **gated tool** (n8n HITL: tool не выполняется без явного human approval). Workflow паузится, UI/webhook/Slack подтверждает.
- После approve: confirmation, audit log («Approved by Catman @ 14:32, pushed to mock ERP»), обновление dashboard.

*Вау + доверие C-level*: «Агент предлагает, человек решает. Никаких необратимых действий без контроля». Идеально снимает страх.

**6\. Закрытие и расширения (1 мин)**

- «Решение передано в back-office. Следующий scheduled run через 7 дней».
- Freeform: «Покажи историю одобрений» или «Смоделируй price increase top-3».
- Workspaces: отдельные вкладки/сессии («Q3 Soft Drinks Optimization»).

### Как обеспечивается «вау», логичность и робастность

**Вау**:  
Визуал (dashboard + generative charts) + multi-agent transparency + real-time status + what-if + seamless insight→decision→action. Выглядит как production copilot, а не PoC.

**Логичность**:  
Прямо повторяет реальный CatMan-процесс (analyze → recommend → decide → execute) + multi-agent gatekeeper + HITL на границе high-risk. Подтверждается практиками AI в category management (assortment optimization, store-specific, scenario simulation, copilots).

**Робастность для презентации (критично!)**:

- **Demo mode**: Флаг/переключатель — использует pre-computed хорошие ответы + fixed data path (детерминизм).
- Fallbacks: Если LLM/tool fails → cached last good analysis + сообщение «Using previous validated insights».
- Error handling: Max iterations, output validation (JSON schema), Error Trigger, retry, friendly UI messages + «Retry / Manual override».
- Timeouts + progress indicators (чтобы не «висело»).
- Pre-seeded data + offline charts (не зависит от внешних API в момент демо).
- Audit trail + logs (можно показать n8n execution для transparency).
- Mock write-tools (не трогаем реальный prod).
- Backup: Записанное видео + скриншоты + dual-screen (UI + n8n canvas).
- Edge-case demo (опционально): ambiguous query → clarification via chat/HITL.
- Security: Least privilege, no secrets, auth на webhooks.

Дополнительно: Guardrails (topical, PII), token monitoring, versioned prompts.

## Блок 1: n8n 2.0 + графы + AI-агенты

### ✅ Что верно

[5](https://www.jahanzaib.ai/blog/n8n-ai-agent-workflows-practitioner-guide) n8n выигрывает на сложных, высоконагруженных, data-sensitive воркфлоу; 2.0-релиз изменил фундамент: n8n теперь трактует LangChain как гражданина первого класса, и 70+ специализированных AI-нод покрывают весь агентный стек. [5](https://www.jahanzaib.ai/blog/n8n-ai-agent-workflows-practitioner-guide) Визуальный канвас делает воркфлоу читаемым для не-разработчиков, \*\*но\*\* конфигурация AI-агента (выбор типа памяти, описание инструментов, системный промпт, лимит итераций) требует человека, понимающего, как рассуждают LLM.

### ⚠️ Подводные камни, которые агент не упомянул

**Камень 1: Детерминированность vs. агентность — это архитектурный выбор, а не просто фича.**

[4](https://blog.n8n.io/we-need-re-learn-what-ai-agent-development-tools-are-in-2026/) Детерминированная логика важна не для выполнения функций, а для обеспечения того, чтобы агенты проходили через набор предопределённых процессов. Например, вы хотите, чтобы агент в security operations \*\*всегда\*\* проверял URL в VirusTotal — вы не хотите, чтобы он рассуждал и, возможно, пропустил эту проверку. Для Catman это означает: часть логики (например, обязательное логирование решений, обращение к конкретным справочникам) должна оставаться жёстко детерминированной нодой, а не передаваться в рассуждение агента.

**Камень 2: Агент может зациклиться и сжечь API-бюджет.**

[8](https://aiwiner.com/how-to-build-ai-agents-n8n-2026/) Установите максимальный лимит итераций в ноде AI Agent (по умолчанию 10), чтобы предотвратить бесконтрольные расходы на API.

**Камень 3: Чувствительные данные в логах.**

[3](https://hatchworks.com/blog/ai-agents/n8n-best-practices/) История выполнений n8n захватывает входные и выходные данные каждой ноды по умолчанию — это полезно для дебаггинга, но потенциальная ответственность, если через воркфлоу идут чувствительные данные. Correlation ID в production-сетапах систематически игнорируются. Нужно явно определить политику хранения логов выполнений.

### ➕ Что добавить

[5](https://www.jahanzaib.ai/blog/n8n-ai-agent-workflows-practitioner-guide) Рекомендация: пусть технический человек настроит и протестирует ядро воркфлоу, а затем задокументирует части, которые нетехнический оператор (Catman) может безопасно менять — системный промпт и контент базы знаний.

## Блок 2: Claude Code как "архитектор инфраструктуры" для n8n

### ✅ Что верно

[11](https://www.roborhythms.com/claude-n8n-workflow-2026/) Сдвиг от «Claude как советника» к «Claude как строителя» произошёл, когда n8n получил поддержку MCP в начале 2026 года. До этого можно было вставить JSON воркфлоу в Claude и попросить помощи — полезно, но всё ещё вручную. Теперь Claude имеет живой read/write доступ к вашему инстансу n8n: может проектировать воркфлоу с нуля, деплоить их, находить поломки и итерировать в реальном времени.

### ⚠️ Подводные камни, которые агент не упомянул

**Камень 1: Claude Code даёт 40–50% готовности, а не 100%.**

[13](https://dominikgabor.com/blog/will-claude-code-replace-n8n.html) Claude Code получает воркфлоу на 40–50% правильно. n8n обрабатывает сложность, с которой ИИ не справляется. Это не «пишем ТЗ → получаем готовый воркфлоу». Нужны итерации и человек с n8n-грамотностью для финального review.

**Камень 2: Credentials Claude Code не ставит — это ручная работа.**

[15](https://medium.com/ai-systems-lab/best-n8n-workflows-to-build-with-claude-code-2026-a7974cabe9dc) Есть одно ограничение, применимое к каждому воркфлоу: Claude Code \*\*не может задать credentials\*\*. Он может сконфигурировать ноду на ссылку на credential по имени, но Telegram bot token, Google OAuth, API-ключи — всё это уже должно существовать в n8n и выбираться вручную.

**Камень 3: Dangerous Mode — это реальный риск в production.**

[12](https://www.ability.ai/blog/claude-code-n8n-workflows) Для эффективной работы Claude Code требует включения «Dangerous Mode», который обходит проверки разрешений для каждого редактирования файла или команды терминала. Это ускоряет разработку, но требует доверенного окружения.

**Камень 4: Сложные webhook-аутентификации — стабильная точка отказа.**

[11](https://www.roborhythms.com/claude-n8n-workflow-2026/) Слабые места в порядке частоты столкновения с ними: аутентификация вебхука с нестандартными заголовками — Claude часто неверно устанавливает тип аутентификации для входящих вебхуков от сервисов с кастомными форматами заголовков (не Bearer token, не Basic).

### ➕ Что добавить

[3](https://hatchworks.com/blog/ai-agents/n8n-best-practices/) Относитесь к изменениям воркфлоу так же, как к изменениям кода — ветка, ревью, мёрдж. Нативная история версий n8n даёт частичное покрытие, но Git одновременно даёт audit trail, рабочий процесс совместной работы и внешний бэкап. [5](https://www.jahanzaib.ai/blog/n8n-ai-agent-workflows-practitioner-guide) Практический совет по стоимости: маршрутизация простых запросов к gpt-4o-mini, а сложных — к Claude 3.5 Sonnet может сократить расходы на агента на 60% и более в production.

## Блок 3: Фронтенд — чат или дашборд

### ✅ Что верно

Тезис о том, что «просто чат-бокс» недостаточен для C-level демо — верен и подтверждён практиками.

### ⚠️ Подводные камни

**Камень 1: HITL-апрувал в n8n имеет неочевидные production-ограничения.**

[21](https://humangent.io/blog/n8n-human-in-the-loop-guide) Рецензент \*\*всегда\*\* переходит на страницу браузера для ответа — нет инлайн-апрувала внутри Slack/Teams. Нет истории предыдущих решений, нет способа видеть другие ожидающие ревью от того же рецензента. Получатели — channel-specific захардкоженные ID на ноду. Добавление нового рецензента означает редактирование воркфлоу. Рецензенты не могут сами выбрать или сменить канал доставки.

**Камень 2: HITL без таймаута = зависший воркфлоу.**

[22](https://blog.n8n.io/human-in-the-loop-automation/) Каждый HITL-чекпоинт нужен safety net. Рецензенты иногда пропускают уведомления, и воркфлоу не может висеть в ожидании бесконечно. В n8n комбинирование таймаута Wait-ноды с IF-ветвлением позволяет задачам автоэскалироваться, откладываться для последующего ревью, уведомлять резервных владельцев или дефолтиться к безопасному исходу.

**Камень 3: HITL — это не только «одна кнопка approve».**

[19](https://medium.com/@automation.labs/n8n-tool-approval-gates-the-hitl-pattern-for-production-agents-18caaec7c1be) Старый паттерн на Wait-ноде просит человека одобрить \*\*вывод\*\*, который агент уже произвёл. Новый паттерн просит одобрить \*\*вызов инструмента до того\*\*, как агент его выполнит — другой радиус поражения, другой audit trail, другая история восстановления. Важно различать эти два паттерна при проектировании.

### ➕ Что добавить

**HITL-паттерн нужен для системного промпта агента:**

[17](https://docs.n8n.io/advanced-ai/human-in-the-loop-tools/) Для корректной интерпретации и обработки отклонённых вызовов инструментов агентом — включите информацию о настройке human review в ваш системный промпт. Это помогает AI понять, какие инструменты требуют апрувала, и корректно реагировать, когда вызов инструмента отклонён.

**Разделяйте гейтованные и свободные инструменты:**

[20](https://n8nautomation.cloud/blog/n8n-human-in-the-loop-approval-ai-agent-workflows) Гейт применяется на уровне инструмента, а не воркфлоу. Это означает, что ваш агент может свободно использовать негейтованные инструменты (поиск в базе знаний, чтение данных), при этом всё ещё требуя апрувал для чувствительных операций (отправка email, обновление записи).

## Блок 4: Архитектура "QlikView-style" дашборд + чат + расписание

### ✅ Что верно

Архитектурный выбор (дашборд + встроенный чат + approval-gate + scheduler) — это наиболее зрелый паттерн для аналитических агентов в 2026 году.

### ⚠️ Подводные камни

**Камень 1: Self-hosted vs Cloud — выбор с production-последствиями.**

[9](https://automationatlas.io/guides/building-ai-agents-with-n8n-2026/) Для агентных нагрузок self-hosting часто предпочтителен, потому что: долгие вызовы модели (10–60 секунд) потребляют cloud execution time; латентность vector store зависит от co-location с рантаймом n8n; локальные модели через Ollama требуют self-hosted ноды с GPU.

**Камень 2: "Работает в тесте" ≠ "работает в production".**

[6](https://blog.n8n.io/best-practices-for-deploying-ai-agents-in-production/) В production агент внезапно таймаутится под реальной нагрузкой, затраты на API растут, алерты об ошибках заполняют почту, пользователи сообщают о непоследовательных ответах. Разрыв между «работает на моей машине» и «справляется с production-трафиком надёжно» больше, чем большинство строителей ожидают.

**Камень 3: Деплой — не финишная черта.**

[6](https://blog.n8n.io/best-practices-for-deploying-ai-agents-in-production/) Для безопасного обновления используйте канареечный деплой: 5% запросов идут на новую версию, 95% на старую. Мониторьте частоту ошибок и время ответа, затем постепенно увеличивайте.

### ➕ Что добавить

**Observability — это не опция, это обязательное требование:**

[3](https://hatchworks.com/blog/ai-agents/n8n-best-practices/) Для команд на n8n Pro или Enterprise нативный Insights dashboard (доступен с v1.89.0) отслеживает production executions, частоту отказов, средние времена выполнения. Команды, получающие наибольшую бизнес-ценность от n8n в 2026 году, — это те, чьи воркфлоу безопасно менять, видны при сбоях и спроектированы для восстановления без вмешательства человека.

**Добавьте HOTL (Human-on-the-Loop) как дополнение к HITL:**

[23](https://blog.n8n.io/human-in-the-loop-vs-human-on-the-loop/) В production эти подходы могут сосуществовать: один воркфлоу иногда содержит оба — AI генерирует 1 000 описаний продуктов (HOTL-мониторинг), но требует human approval перед публикацией топ-50 на главной (HITL-гейт). Этот подход масштабирует человеческое внимание туда, где оно важнее всего.
