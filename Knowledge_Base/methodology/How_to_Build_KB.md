# Методология формирования Knowledge Base (для ИИ-Агентов)

## Принцип S3 (Сущности + Слои + Инструменты)

### Шаг 1. Извлечение сущностей (Entity Extraction)
Из raw data (боли, задачи, отчёты) выделяем **существительные** бизнеса:

Примеры:
- Category, SKU, Supplier, Margin, Forecast, Promo, Decision, AuditTrail

**Инструмент**: Чтение Raw_Data + Claude / GPT с промптом "Extract core business entities".

### Шаг 2. Назначение слоёв (Layer Assignment)
Каждой сущности присваиваем **все слои**, на которых она существует:

Пример для `Margin`:
- L1: Бизнес-правило (целевая маржа)
- L2: Аналитика (расчёт, мониторинг)
- L3: Стратегия (решения)
- L4: Исполнение (обновление цен)
- L5: Память (история маржи)

### Шаг 3. Определение агентов и инструментов
Для каждого слоя сущности определяем:
- Кто манипулирует (Agent)
- Какими инструментами (Tools)

Пример:
- `Margin` @ L2 → Analyst Agent + pandas + statistical tools
- `Margin` @ L4 → Executor Agent + Excel/1C API

### Шаг 4. Вертикальная интеграция
Строим цепочки:
```
Analyst (L2) → Strategist (L3) → Executor (L4) → Governance (L5)
```

### Шаг 5. Документирование
- Создаём Markdown-файл в `entities/`
- Создаём файл агента в `agents/`
- Обновляем `ontology/`

## Правила именования

- Сущности: `PascalCase` (`Category`, `Margin`)
- Агенты: `AgentName_Agent` (`Analyst_Agent`)
- Слои: `L1`, `L2`... + название

## Критерии качества KB

1. Каждая сущность имеет минимум 3 слоя.
2. Каждый агент привязан к конкретным сущностям и слоям.
3. Есть хотя бы одна вертикальная цепочка (L2→L4).
4. Все белые пятна задокументированы.

## Эволюция

- MVP: Markdown + YAML
- v1.5: JSON Schema + граф в Neo4j
- v2.0: OWL + Semantica
