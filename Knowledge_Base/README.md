## 1. Архитектура Knowledge Base

### 1.1. Методология: S3 (Сущности + Слои + Инструменты)

**Фундаментальная техника**:  
**Entity + Layered Architecture** (DDD + Separation of Concerns) + **Agentic Graph** (GRACE-подобный подход).

- **Сущности (Entities)**: "Существительные" бизнеса (Category, SKU, Supplier, Margin, Forecast и т.д.).
- **Слои (Layers)**: Вертикальная декомпозиция — одна и та же сущность существует на разных уровнях абстракции.
- **Инструменты (Tools)**: Действия/агенты, манипулирующие сущностями на конкретных слоях.
- **Граф**: Сущности = узлы, Агенты = рёбра/оркестраторы, Слои = контексты.

**Почему именно так**:
- Соответствует исходной боли проекта: "формируешь сущности, tools и манипулируешь на разных слоях".
- Позволяет строить **вертикально-интегрированных агентов** (аналитик → стратег → исполнитель).
- Легко эволюционирует в **онтологии** (W3C OWL / RDF) или **Semantica-style** графы знаний.

### 1.2. Слои архитектуры (Layers)

| Слой | Название | Назначение | Примеры сущностей | Примеры агентов |
|------|----------|------------|-------------------|-----------------|
| **L1** | **Business / Domain** | Бизнес-логика и правила | Category, SKU, Supplier, Promo, Margin | Domain Rules Agent |
| **L2** | **Analytical** | Анализ, прогноз, insights | Forecast, ABC-XYZ, Drift, Elasticity | Analyst Agent, Watchdog |
| **L3** | **Strategic** | Принятие решений, сценарии | Decision, Recommendation, Scenario | Strategist Agent |
| **L4** | **Execution** | Действия в системах | EmailDraft, ExcelUpdate, 1CTransaction | Executor Agent, Negotiator |
| **L5** | **Governance & Memory** | Аудит, корпоративная память, профиль | AuditTrail, CorporateMemory, UserProfile | Governance Agent, Memory Agent |
| **L6** | **Infrastructure / Integration** | Подключение к внешним системам | 1C, Excel, Email, POS, Marketplace | Integration Agent |

**Вертикальная интеграция**: Агенты работают иерархически — контекст передаётся сверху вниз (L2 → L4), результаты — снизу вверх.

### 1.3. Метод формирования Knowledge Base

**Основной метод (MVP)**:  
**Entity-first + GRACE-like** (граф сущностей + marketplace инструментов)

1. **Извлечение сущностей** из raw data (боли бизнеса, задачи Catman, рыночные отчёты).
2. **Определение слоёв** для каждой сущности.
3. **Привязка инструментов/агентов** к сущностям на слоях.
4. **Оркестрация** через n8n / LangGraph-style workflows.

**Эволюция (будущие версии)**:
- Переход на **W3C OWL / RDF** (онтологии) + **Semantica-agi/semantica** для reasoning.
- Полноценный **Knowledge Graph** с SHACL-валидацией.

**Хранение**:
- Markdown + YAML (текущий MVP)
- JSON Schema для сущностей
- Будущий: Neo4j / RDF store

### 1.4. Папка для записи

**Корневая структура**:
```
/home/user/Catm/Knowledge_Base/
├── README.md                 ← этот файл (архитектура + навигация)
├── entities/                 ← определения сущностей (YAML/JSON/MD)
├── agents/                   ← спецификации агентов
├── layers/                   ← детальные описания слоёв и взаимодействий
├── ontology/                 ← высокоуровневая семантическая модель (готово к OWL)
├── methodology/              ← как строить/расширять KB
├── white_spots/              ← белые пятна и задачи на закрытие
└── sources/                  ← ссылки на raw data (Raw_Data/)
```

## 2. Белые пятна (White Spots) — что необходимо закрыть

### Критические (MVP)
1. **Конкретные сущности non-food ритейла** (fashion, DIY, cosmetics, home textiles) — различия в атрибутах.
2. **Точные паттерны интеграции с 1С** (REST API vs COM vs OData).
3. **KPI-бенчмарки Catman** (маржа +1–3 п.п., снижение потерь промо 15–25%, точность прогноза).
4. **Профиль пользователя / корпоративная память** (Hermes-style).
5. **Multi-agent orchestration** (n8n + LangGraph vs CrewAI vs собственный).

### Средние
- ESG / регуляторные сущности (маркировка "Честный ЗНАК").
- Конкурентная разведка (внешние сигналы).
- Генерация презентаций / Governance-дашборда.
- Локализация (RU + EN).

### Долгосрочные
- Переход на полноценную онтологию OWL.
- Self-hosted LLM + суверенные модели.
- Agentic OS / Cortex-like инфраструктура.

- `идеи_S3_в_бизщнесе...md` — фундамент S3 (сущности + слои).
